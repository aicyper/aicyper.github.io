personal study notes

JavaScript

HTML에 자바스크립트를 연결하는 세 가지 방법 — 외부 파일, 문서 내부 스크립트, 인라인 이벤트 핸들러 — 을 각각 실행해보고, 세 가지를 한 요소에 동시에 걸면 어떤 순서로 실행되는지 확인합니다.

외부에서 — External Script

<script src="app.js">

자바스크립트 코드를 별도의 .js 파일에 작성하고, HTML에서는 script 태그의 src로 그 파일만 불러옵니다. 코드와 마크업이 분리되어 있어 여러 페이지에서 재사용하거나 유지보수하기 좋습니다.

클릭하면 실행 결과가 여기에 표시됩니다
HTML + app.js (외부 파일)
<!-- index.html -->
<button id="btn-external">외부 스크립트 버튼</button>
<script src="app.js"></script>

/* app.js — 별도로 저장된 자바스크립트 파일 */
document.getElementById('btn-external')
  .addEventListener('click', function () {
    console.log('외부 파일(app.js)에서 실행됨');
  });
src="app.js"
HTML 안에 코드를 적지 않고, 이 경로에 있는 파일을 불러와 실행합니다.
분리 구조
HTML(구조)과 JS(동작)가 서로 다른 파일에 있어 코드가 길어져도 문서가 깔끔합니다.
재사용
같은 app.js를 여러 HTML 페이지에서 함께 불러와 쓸 수 있습니다.
주의
script 태그가 버튼보다 먼저 나오면 아직 없는 요소를 찾다 오류가 나므로, 보통 body 끝이나 defer와 함께 씁니다.

내부에서 — Internal Script

<script> ... </script>

별도 파일 없이, HTML 문서 안에 script 태그를 두고 그 안에 코드를 직접 작성합니다. 이 페이지처럼 파일 하나로 완결된 데모나 짧은 스크립트에 자주 쓰입니다.

클릭하면 실행 결과가 여기에 표시됩니다
HTML 한 파일 안에서
<button id="btn-internal">내부 스크립트 버튼</button>

<script>
  document.getElementById('btn-internal')
    .addEventListener('click', function () {
      console.log('문서 내부 script 태그에서 실행됨');
    });
</script>
<script></script>
src 없이 태그 사이에 코드를 바로 작성합니다. 파일이 하나뿐이라 배포가 간단합니다.
위치
버튼처럼 조작할 요소를 찾는 코드는 그 요소가 이미 그려진 뒤(대개 body 끝)에 두는 것이 안전합니다.
단점
다른 페이지에서 같은 기능이 필요하면 코드를 복사해야 하므로 재사용이 번거롭습니다.

이벤트 — 인라인 이벤트 핸들러

onclick="..."

script 태그 없이, 태그의 속성(onclick, onmouseover 등)에 실행할 코드를 바로 적습니다. 가장 빠르게 붙일 수 있지만, 마크업과 동작이 한 줄에 섞여 코드가 많아지면 관리하기 어렵습니다.

클릭하면 실행 결과가 여기에 표시됩니다
HTML 태그의 속성으로
<button id="btn-inline" onclick="handleInlineDemo()">
  인라인 이벤트 버튼
</button>

<script>
  function handleInlineDemo() {
    console.log('onclick 속성에서 바로 실행됨');
  }
</script>
onclick="함수()"
클릭 시 실행할 코드를 속성값으로 직접 적습니다. 내부적으로는 element.onclick에 함수를 대입한 것과 같습니다.
장점
요소 하나에 코드 한 줄만 붙이면 되어 가장 간단합니다.
단점
HTML과 로직이 섞이고, 같은 요소에 onclick을 또 대입하면 이전 것을 덮어써 하나만 남습니다.

세 가지를 동시에 걸면?

external + internal + inline

같은 버튼 하나에 외부 스크립트, 내부 스크립트, 인라인 onclick을 모두 걸어봤습니다. addEventListener로 등록한 것들은 서로 덮어쓰지 않고 쌓이기 때문에, 클릭 한 번에 세 가지가 전부 실행됩니다.

클릭하면 실행 순서가 여기에 표시됩니다
한 버튼에 세 가지 방식을 모두 연결
<button id="btn-combined" onclick="handleCombinedInline()">
  동시 적용 버튼
</button>

/* ① 외부 파일(app.js)이라고 가정 */
btn.addEventListener('click', function () {
  console.log('외부 스크립트 실행');
});

/* ② 문서 내부 script 태그 */
btn.addEventListener('click', function () {
  console.log('내부 스크립트 실행');
});

/* ③ 인라인 onclick 속성 (위 태그에 이미 적용됨) */
function handleCombinedInline() {
  console.log('인라인 이벤트 실행');
}
1인라인 onclickHTML을 파싱하는 시점에 이미 element.onclick으로 등록되어 있어 가장 먼저 실행됩니다.
2외부 스크립트addEventListener로 등록된 순서대로 실행 — 이 데모에서는 먼저 등록됐습니다.
3내부 스크립트역시 addEventListener로 등록 — 나중에 등록된 만큼 마지막에 실행됩니다.
※ 핵심
  • onclick 속성과 addEventListener는 서로 다른 방식으로 등록되며, 함께 있어도 둘 다 실행된다.
  • addEventListener는 여러 번 호출해도 계속 쌓이지만, element.onclick = fn 처럼 직접 대입하는 방식은 나중 것이 이전 것을 덮어쓴다.
  • 실행 순서는 "등록된 순서"를 따른다 — 인라인 onclick은 HTML 파싱 시점에 가장 먼저 등록되므로 보통 가장 먼저 실행된다.
방식작성 위치여러 개 등록 시
외부 스크립트별도 .js 파일 + srcaddEventListener면 누적
내부 스크립트문서 안 <script>addEventListener면 누적
인라인 이벤트태그의 on* 속성다시 쓰면 이전 것을 덮어씀
